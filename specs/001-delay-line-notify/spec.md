# Feature Specification: 電車遅延通知 Phase 1（MVP）

**Feature Branch**: `001-delay-line-notify`
**Created**: 2026-05-28
**Status**: Draft
**Input**: User description: "電車遅延通知Bot Phase 1（MVP）: 1路線の遅延検知 → LINE通知（代替路線なし）"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 朝の通勤前に遅延通知を受け取る (Priority: P1)

毎朝、出発前の時間帯（デフォルト: 平日6:00〜9:00）に、監視対象路線の遅延状況が自動でLINEに届く。遅延が発生している場合のみ通知が届き、追加の操作なしに対処を判断できる。

**Why this priority**: 本機能の中核価値。ユーザーが能動的に確認しなくても遅延を知れることがMVPの達成条件。

**Independent Test**: 監視対象路線に遅延がある状態でスクリプトを実行し、LINEに遅延通知メッセージが届くことを確認する。

**Acceptance Scenarios**:

1. **Given** 総武線（浅草橋駅→御茶ノ水駅）が10分以上遅延している, **When** 通知時間帯内にスクリプトが実行される, **Then** 路線名・遅延状況を含む通知がLINEに届く
2. **Given** 同じ遅延についてすでに通知済みである, **When** 5分後に再度スクリプトが実行される, **Then** LINEへの追加通知は送信されない
3. **Given** 総武線（浅草橋駅→御茶ノ水駅）が正常運行または遅延10分未満, **When** 通知時間帯内にスクリプトが実行される, **Then** LINEには何も届かない
4. **Given** 通知時間帯外にスクリプトが実行される, **When** 実行がトリガーされる, **Then** 遅延チェック自体を行わず何も届かない
5. **Given** 遅延情報の取得に失敗した, **When** スクリプトが実行される, **Then** LINEへの通知は送信されず、エラーがログに記録される

---

### User Story 2 - 通知内容を確認して対処を判断できる (Priority: P2)

届いた通知を見るだけで、どの路線がどのくらい遅延しているかを把握し、出発を遅らせるなど対処の判断ができる。

**Why this priority**: 通知を受け取っても内容が不十分では行動できない。通知の質がUX直結する。

**Independent Test**: 遅延通知のメッセージ内容に、路線名・遅延状況が含まれることを単体で検証できる。

**Acceptance Scenarios**:

1. **Given** 遅延通知が届いた, **When** ユーザーが通知を開く, **Then** 路線名・遅延内容（原因やおおよその遅延分数）が含まれるメッセージが表示される
2. **Given** 遅延通知が届いた, **When** ユーザーが通知を確認する, **Then** 代替路線の情報は含まれない（Phase 2以降の機能）

---

### Edge Cases

- 遅延情報の取得APIがタイムアウト・エラーを返した場合: 通知は送信せず、エラーをログに記録する
- 通知時間帯外にスクリプトが実行された場合: 遅延チェックを行わず何もしない
- 同じ遅延が継続している場合: 最初の1回のみ通知し、遅延が解消されるまで再通知しない（通知済み状態を記録して管理する）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは指定された1路線の遅延情報を通知時間帯内に定期的に確認しなければならない（5分間隔）
- **FR-002**: システムは予定時刻より10分以上の遅延を「遅延あり」と判定しなければならない
- **FR-003**: システムは「遅延あり」と判定した場合のみLINEへ通知を送信しなければならない
- **FR-004**: 遅延通知メッセージには路線名・遅延内容（原因・遅延状況）を含めなければならない
- **FR-005**: システムは通知時間帯外にはチェックを実行しない。デフォルトの通知時間帯は平日6:00〜9:00とする
- **FR-006**: システムは遅延情報の取得失敗時にエラーをログに記録し、通知は送信しない
- **FR-007**: 監視対象路線は「総武線（浅草橋駅 → 御茶ノ水駅）」の1路線とする

### Key Entities

- **監視路線**: 監視対象の路線名・区間。Phase 1では1路線のみを固定設定
- **遅延情報**: 路線ごとの遅延有無・遅延内容（原因・遅延分数）
- **通知メッセージ**: LINEへ送信するメッセージ。路線名・遅延状況を含む

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 遅延発生から通知到達まで5分以内
- **SC-002**: 通知時間帯内（平日6:00〜9:00）に遅延が発生した場合、通知到達率100%
- **SC-003**: 遅延なし時に通知が届く誤報率ゼロ
- **SC-004**: 通知メッセージを読むだけで（追加操作なしに）遅延状況を把握できる

## Assumptions

- 対象ユーザーは本人のみ（個人利用）。複数ユーザー対応はスコープ外
- 監視路線は「総武線（浅草橋駅 → 御茶ノ水駅）」の1路線を初期設定で固定する。Phase 1では動的な登録・変更機能は不要（Phase 2以降）
- 代替路線の提示はPhase 2以降の機能としてスコープ外
- 遅延判定基準は10分以上の遅延とする（Raildar要件定義書にて確定済み）
- 通知時間帯のデフォルトは平日6:00〜9:00
- 同一遅延の重複通知は行わない。遅延が解消されるまで再通知しない
- 平常運転時の「安心通知」はPhase 2以降の機能としてスコープ外
