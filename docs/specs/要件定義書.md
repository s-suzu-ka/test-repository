# 要件定義書

## プロジェクト概要

- **プロジェクト名**: 電車遅延通知Bot（仮称）
- **目的**: 利用路線に遅延が発生した場合のみ、代替路線とともにLINEで通知することで、朝のバタバタした時間でも能動的に確認しなくても遅延に対処できるようにする
- **対象ユーザー**: 本人のみ（個人利用）
- **採用する方向性**: 方向性B（LINE通知Bot）

## 機能要件

### 必須機能（Must Have）

| 機能名       | 概要                                                 | 備考                                 |
| ------------ | ---------------------------------------------------- | ------------------------------------ |
| 遅延監視     | 登録した路線の遅延情報を定期取得する                 | 出発時間帯（例：6〜9時）のみ監視でOK |
| 遅延通知     | 遅延が検知されたときのみLINEに通知する               | 遅延なし時は通知しない               |
| 代替路線提示 | 遅延発生時に代替となる路線・乗り換え案を通知に含める | 乗換案内APIと連携                    |
| 路線登録     | 監視する路線を設定できる                             | 初期設定時に1路線以上登録            |

### あると良い機能（Should Have）

| 機能名           | 概要                           | 備考                     |
| ---------------- | ------------------------------ | ------------------------ |
| 通知時間帯の設定 | 監視する時間帯を変更できる     | 休日は通知不要などの制御 |
| 遅延解消通知     | 遅延が解消されたことも通知する | 外出中の判断に役立つ     |

### 将来的な拡張（Could Have）

| 機能名                  | 概要                                       | 備考        |
| ----------------------- | ------------------------------------------ | ----------- |
| 複数路線の監視          | 乗り換えを含む複数路線を一括監視           | Phase 2以降 |
| 平日/休日の自動切り替え | カレンダー連携で通知スケジュールを自動調整 | Phase 2以降 |

## 非機能要件

- **パフォーマンス**: 遅延発生から通知まで5分以内
- **セキュリティ**: LINEのアクセストークンを環境変数で管理し、コードに直書きしない
- **可用性**: 朝の通勤時間帯（6〜9時）に安定稼働していれば十分
- **スケーラビリティ**: 個人利用のため拡張性は最低限でOK

## 技術スタック（推奨）

### バックエンド（スクリプト）

- **TypeScript**: 学習コストが低く、フロント・バック両面で汎用性が高い

### 遅延情報取得

- **Yahoo!路線情報 / 鉄道遅延なう API** などの遅延情報API: 国内路線の遅延情報を取得できる

### 代替路線

- **Yahoo!乗換案内API** または **国土交通省 公共交通オープンデータ**: 乗り換え候補の取得

### 通知

- **LINE Messaging API**: 個人のLINEにメッセージ送信。無料枠で個人利用は十分

### 実行環境

- **GitHub Actions** または **Render（無料枠）**: 定期実行（cron）でスクリプトを動かす。サーバー管理不要

## 技術スタック選定の根拠

個人利用の小規模ツールのため、サーバー管理が不要なサーバーレス構成を推奨しています。PythonはAPI連携コードの書きやすさと情報量の多さから選定。通知先はすでに日常的に使っているLINEにすることで、専用アプリのインストールなしに運用できます。

## 開発フェーズ案

- **Phase 1（MVP）**: 特定1路線の遅延検知 → LINEへの通知（代替路線なし）。目安：1〜2日
- **Phase 2**: 代替路線の提示を追加。通知時間帯の設定。目安：2〜3日
- **Phase 3**: 複数路線対応・休日スキップ・遅延解消通知。目安：別途検討
